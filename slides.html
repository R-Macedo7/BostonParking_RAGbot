Data Engineering
Source-Specific Chunking
Uniform token-based splitting destroys semantic coherence in structured civic data. Each source gets a strategy matched to its document structure.
Violations · HTML Table
1 Chunk Per Violation
Rows serialized to natural language — improves embedding quality vs raw tabular encoding. Dedicated chunks for zone comparison (Zone A vs B) and violation summaries. Guarantees atomic retrieval per violation type.
Street Cleaning · 3,758-row CSV
Segment Assembly Per Street
Raw CSV has one row per street segment. Odd/even sides, times, and week patterns assembled into a single natural-language chunk per street. Enables direct street-name lookup without multi-hop retrieval.
BTD Traffic Rules · 80-page PDF
Section-Aware Splitting
Splits on Article/Section headers — not token count. Hollow header chunks under 150 chars filtered post-extraction. Cross-reference integrity and regulatory context preserved within each chunk.
Permits & Towing · HTML
Intent-Clustered Key Facts
High-frequency intent patterns receive dedicated atomic chunks: tow lot address, hours, fees, payment — guaranteeing Rank 1 retrieval for the most critical queries regardless of phrasing variation.

Domain Filter
Before searching, the system figures out what kind of question is being asked — a fine, a street schedule, a permit question, or a towing issue. This narrows the search so it only looks in the right place.
5 domains · keyword scoring · boost rules
Query Splitting
If someone asks two questions at once — "What's the hydrant fine and does street cleaning run on holidays?" — GPT-5.4 Nano splits it into separate searches, each answered precisely, then merged.
GPT-5.4 Nano · triggers on multi-intent
Dual Search
We run two searches simultaneously. BM25 finds exact keyword matches (great for street names and dollar amounts). ChromaDB finds semantically similar content (great for paraphrased questions).
BM25 Top-10 + ChromaDB Top-10
RRF Fusion
The two result lists are merged using Reciprocal Rank Fusion — a mathematical technique that promotes chunks appearing in both lists without needing to compare their raw scores, which are incompatible.
Σ 1/(60 + rank) · Top-5 selected
Answer Synthesis
GPT-5.4 reads the top 5 retrieved chunks and writes a plain-English answer — constrained to only cite facts from those chunks. Simple questions use the cheaper Nano model; complex ones route to Mini.
Nano or Mini · T=0.0 · citation-only
Generation Layer
Complexity-Aware Model Router
A lightweight routing layer selects between two GPT-5.4 models at inference time — minimizing cost on simple lookups without sacrificing precision on regulatory synthesis.
GPT-5.4 Nano · ~$0.20 / 1M tokens
Simple Lookups + Decomposition
Handles: fine amounts, schedule queries, single-domain fact retrieval, query decomposition sub-calls.

Routing condition: retrieved chunks span ≤1 domain AND no complexity signals in query text ("unless", "except", "still need to").

53 of 84 eval queries routed to nano.
GPT-5.4 Mini · ~$0.75 / 1M tokens
Regulatory Synthesis
Handles: cross-domain queries, exception resolution, multi-rule conflict (e.g. holiday + overnight + tow interaction).

Routing condition: retrieved chunks span >1 domain OR complexity signals detected in query.

31 of 84 eval queries routed to mini.

Safety & Reliability
Built-In Guardrails
Deliberate design decisions to prevent hallucination and ensure trustworthy answers
Citation-Only Answers
The system prompt explicitly forbids the model from asserting any fact not present in the retrieved chunks. If the answer isn't in the corpus, the model says so — it cannot fill gaps with general knowledge.
Zero hallucinations across 84-query eval set
Temperature = 0.0
Both models run at temperature zero. Regulatory answers about fines, permit rules, and towing fees must be deterministic — the same question must always return the same answer, with no random variation.
Applies to Nano and Mini equally
Out-of-Scope Refusal
Queries that score low across all 5 domain classifiers fall through without a domain filter, then retrieve against the full corpus. If still no relevant chunks are found, the system declines to answer rather than guessing.
3 OOS queries correctly handled in eval
Domain Filtering as a Guardrail
The domain classifier doesn't just improve performance — it prevents cross-contamination. A question about permit fees will never retrieve towing chunks, so the model can't accidentally blend unrelated regulations.
5 isolated domains · metadata-filtered queries
Source Attribution
Every answer surfaces the source documents it drew from — official boston.gov pages that users can click to verify. This keeps the system accountable and lets users check primary sources directly.
Linked citations on every bot response
Known Limitations
2 of 84 queries missed: one due to a pedestrian zone corpus gap, one due to towing keyword phrasing. Both are corpus limitations, not model failures — the model did not hallucinate a wrong answer.
98% recall — 2 misses are data gaps, not hallucinations
